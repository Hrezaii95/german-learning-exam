# A1.1 expansion and coherent study selection

The full scope is all twelve A1.1 lessons. The first owner review milestone is a complete, live, verified release through Lesson 6. Work proceeds in lesson order; later content must not hide gaps in earlier lessons.

## Sequence

0. Publish the requested questions cheat sheet first: W-question map, sentence order, yes/no questions, ja/nein/doch, pronunciation, dictionary and saved review. Clearly separate core patterns from the wider question family.

1. Audit and repair Lessons 1–4: every book page, source vocabulary, verbs, grammar, phrases, listening/transcripts, answer keys, dictionary, practice and saved review. Establish a shared lesson, concept and source taxonomy and a persistent selection control.
2. Add Lesson 5 from the supplied coursebook, workbook, glossary, recordings, transcripts and answer key. Integrate all features, then verify coverage and interactions.
3. Add Lesson 6 using the same process; include Module 2 review, grammar, communication and test pages. Verify the cumulative experience through Lesson 6, deploy and verify live for owner review.
4. Continue Lessons 7–12 in order under the full expansion objective. Do not label the whole A1.1 goal complete at the Lesson 6 milestone.

## Selection contract

- One shared control offers all available lessons, one lesson, any combination, and all lessons up to a chosen lesson.
- Selected lessons are combined with OR. Selected concepts are combined with OR. Lesson, concept and source filters combine with AND.
- Empty selections show an honest empty state, never silently reset to all content.
- Selection persists between app sections and reloads. Counts and review queues use the actual selected records.
- Teacher extras carry both `Teacher extra` and their source-supported lesson membership; profession extras belong to Lesson 2. Topic tags describe the taught concept separately from part of speech.
- Direct links remain reachable, with clear treatment of content outside the current selection.

## Evidence and release gates

Use source-page and source-item inventories for each lesson, independent counts and ID comparisons, meaningful filter/state tests, existing regression suites, `npm run check`, `npm run gates:pages`, desktop/mobile browser journeys, byte-checked media and successful GitHub Pages deployment. Confirm the same behavior on the live URL. Missing source answers must stay explicitly unavailable; sample answers and study explanations must remain labelled.
