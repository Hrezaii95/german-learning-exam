# German Learning OS — whole-app UI/UX audit

**Audited 18 September 2026. Reference standard: 01 Countries & languages and 02 Home & furniture.**

## Assessment

The app contains useful learning material and several strong interactive teaching tools, but it does not yet behave or look like one coherent product. The most urgent defects affect readable layouts, reliable saving, and truthful controls. A second group concerns navigation, overwhelming page length, inconsistent cards, audio, and dictionary interactions. Visual teaching improvements should follow those repairs and extend the strongest existing tools.

The approved sheets establish the right direction: **see the pattern → explore an example → hear it → understand it → recall it → save what needs practice.** Their color trails, spatial memory cues, and short explanations should become reusable product conventions. Copying their page length or putting every topic into identical colored boxes would miss their value.

This is an audit and proposed work list. No application changes or deployment were made during this audit.

## Scope and evidence

- Inspected the live public site: https://hrezaii95.github.io/german-learning-exam/.
- Captured **58 routes**, covering every primary page family, all 12 lesson landing pages, all 15 cheat sheets, and representative vocabulary, profession, grammar, verb, phrase, activity, practice, and review details.
- Captured desktop **1440 × 1000** and phone **390 × 844** layouts. Also checked Lessons 12, Professions, the book reader and Countries at 320 and 768 pixels.
- Read relevant component and styling implementations to explain observed behavior; used isolated browser data for save, reload, quiz, filter, audio, and export tests.
- All 58 initial route checks returned HTTP 200 without a captured uncaught page error. No document-level horizontal overflow was recorded at 390 pixels. These checks **do not establish usability**: the worst desktop wrapping defect passes both.
- Evidence: [route inventory](inventory.json), [interaction results](interaction-findings.json), [follow-up results](followup-findings.json), screenshots in this directory. Script selector timeouts are preserved in the evidence; findings preceding them completed. Corrected follow-up checks completed the audio-preference and mobile-menu checks.
- This is not a claim that every generated detail page, every exercise answer, every recording, every browser, or every assistive technology has been individually reviewed. Native German pronunciation quality, physical-device Safari behavior, full screen-reader navigation, measured contrast, throttled-network performance, and complete offline recovery still need dedicated validation.

## The shared standard to establish

| Area | Required standard |
|---|---|
| First screen | Clear topic, what the learner will be able to do, one useful starting action, compact scope and navigation. Avoid an initial screen consisting mainly of controls or internal status. |
| Teaching sequence | A compact overview, a focused explanation/explorer, a worked example, short recall, then optional reference depth. |
| Color | Stable noun genders: blue masculine, pink feminine, green neuter, purple plural. Always pair color with article/label; distinguish grammatical gender from a person's identity. Define separate named conventions for sentence roles and feedback. |
| Typography | Shared body and German-example scale, inherited form-control fonts, comfortable line lengths, readable secondary text, predictable heading hierarchy. |
| Layout | Consistent page widths, spacing, card surfaces, section navigation, and controls. Different content can have different diagrams without becoming a different app. |
| Word interaction | Word or phrase → meaning/card → pronunciation → save/remove. Preserve context when returning. Supported actions work consistently on touch, mouse, and keyboard. |
| Pronunciation | A recognizable player beside useful German examples, with truthful original/generated labels, shared preferred speed, active state, stop/repeat, and useful failure recovery. |
| Saving and progress | One meaning for Saved, Reviewed, Due, Read, and Completed; persistence and backup match the learner's expectation. |
| Mobile | Content becomes simpler and readable as space shrinks. Navigation and dictionary never conceal the focused action. Wide visual maps have an obvious readable alternative. |
| Source information | Maintain attribution, original/generated distinctions, and uncertainty. Put detailed production and verification history in expandable source information rather than the main learning path. |

## Visual and interaction brief for each cheat sheet

These are extensions and refinements of existing tools. Several proposed mechanisms already exist in part and should be improved rather than rebuilt indiscriminately. Every sheet should support a compact overview, an accessible focused explorer, pronunciation, saved review, brief recall, and a genuinely concise printable summary.

| Sheet | Preserve | Specific changes / visual teaching brief |
|---|---|---|
| **01 Countries & languages** | Flags, selected-country map, color/article groups, AUS transformation, location/destination distinctions. | Preserve as reference. Make overview usable at phone size with selected-country focus and a readable list alternative. Keep flags as identity cues, article labels as grammatical cues. Compact chooser; print the pattern and exceptions, not the complete interactive page. |
| **02 Home & furniture** | Illustrated household vocabulary, article/plural/pronoun color trails, focused learning and recall. | Preserve as reference. Improve compact whole-room overview and object focus; keep tiny hotspots accessible with equivalent list controls. Put save/audio consistently beside the selected word; reduce the long reference tail. |
| **03 People, family & work** | Family-generation structure and relationship examples. | A true interactive family tree with an explicit viewpoint: whose mother/brother/partner? | **04 Verbs & sentences** | Conjugation dial and sentence manipulation. | One-screen person → stem → ending map; movable sentence slots with the verb position visible; irregular changes highlighted and labelled. | **05 Numbers & prices** | Number builder and recall tools. | A place-value/reading-direction graphic, units-before-tens cue, and price-tag examples. Pair number hearing with typing/choice recall. ## Cross-cutting release requirements

1. **Responsive and readable:** check 320, 390, 768 and 1440 pixels, text enlargement and zoom. No ordinary paragraph occupies a decorative number column. The main learning content is visible early; controls do not cover focused content. Diagrams have readable small-screen forms, not merely overflow suppression.
2. **Consistent components:** shared colors, controls, typography, word cards, save states and audio states. Test the approved sheets as visual references so global fixes do not damage them.
3. **Reliable state:** save on a card, see it in the collection, rate it, reload, resume, export, import into a fresh profile, and recover the same learning data. Verify both add and remove actions, and meaningful bulk selection.
4. **Honest filters:** test one lesson, several lessons, one concept, combined filters, zero results and out-of-scope deep links. Displayed counts must match the rendered set and the practice pool. Check metadata-derived counts against actual search matching.
5. **Audio and transcript integrity:** verify real playback, preferred rate, changing tracks, interrupted loading, missing audio and fallback labels. Test keyboard and touch access. Language/listening approval requires a separate qualified human review; a successful network response is not pronunciation approval.
6. **Dictionary and selection:** word lookup, phrase selection, matched-card opening, unmatched phrase handling, audio, save and return work across book, sheets, cards and transcripts. Avoid sending a user to an external translator without saying so.
7. **Accessibility:** visible focus, meaningful labels, logical headings, dialog focus/return, keyboard alternatives to drag/hotspots, color-independent cues, contrast measurement, reduced motion, touch-target spacing, and screen-reader task checks. Do not infer conformance from automated checks alone.
8. **Learning feedback:** every task has a clear prompt, answer/reveal state, useful explanation, next step and restart. Reading, self-rating, objective answers and scheduled recall remain distinct. Examples and answer keys are accurately labelled.
9. **Performance and resilience:** measure large libraries on a throttled mid-range phone profile; bound rendered rich content and audio initialization; verify loading/empty/error/offline states and upgrade/cache behavior. Current page-height evidence warrants testing, but does not itself prove load-time or battery impact.
10. **Editorial consistency:** remove stale lesson ranges and production jargon from primary flows; keep source attribution available; use consistent names, punctuation, German spelling, plural notation and du/Sie conventions. Audit English explanations as teaching text as well as German source fidelity.
